# BA-Starter-Kit

Готовий робочий простір бізнес-аналітика для роботи в парі з Claude Code. Склонуй його, налаштуй, працюй. Вся методологія, правила, підказки та живі приклади знаходяться всередині. Це стартовий комплект, а не готовий проект, це каркас, звички, інструменти та зразки. Вміст (твої зустрічі, вимоги, завдання) ти заповнюєш сам.

Цей README, також карта комплекту. Посилання на все нижче. Якщо не знаєш, з чого почати, читай з початку до кінця.

---

## Що це та чому

Уяви помічника, що сидить поруч і пам'ятає кожну домовленість, веде журнал, пише протоколи зустрічей, малює схеми, закладає завдання в Jira й ніколи не втомлюється. Це Claude Code, а цей репозиторій навчає його працювати так, як потрібно бізнес-аналітику, за правилами, твоєму стилю, з твоєю структурою документів.

Два шари:
- Для людини (цей README й папка [docs/](docs/README.md)): простою мовою, крок за кроком, без жаргону.
- Для машини ([CLAUDE.md](CLAUDE.md), [PROJECT-RULES.md](PROJECT-RULES.md), тека `.claude/`): правила та посібники, які Claude читає й виконує самостійно.

Чотири жорсткі правила (записані в [CLAUDE.md](CLAUDE.md), Claude дотримується їх сам): без емодзі, без довгого дефісу, специфікація це суха довідка, вимога каже що, а не як ([what-not-how.md](.claude/rules/what-not-how.md)).

## Модель: твій приватний репозиторій плюс спільне ядро

Це важливо, тому прочитай один раз.

- Твій робочий репозиторій має свій власний приватний git remote. Тут розташовується твій вміст, твої журнали й твої особисті специфіки. Це безпечно для NDA: ніщо твоє не викладається у спільне місце.
- Спільне ядро розташовується на окремому обмінному remote `dataforest-ai/BA-WorkSpace-Claude`. Ти завантажуєш оновлення з нього (нові skills, поліпшені правила). Ти вносиш внески, відкриваючи PR проти нього.

Отже, на одному клоні два remote: твій приватний origin (все) й спільне ядро (skills й правила, які ти обмінюєш).

Особисте проти спільного, правило, яке це робить: skills це безособові шаблони. Вони не містять імен клієнтів, префіксів, ключів Jira, шляхів. Вони читають це з твоїх особистих джерел під час виконання:

- `.claude/skills/ba-track-tasks/tasks.local.md`, твій реєстр завдань (поточний проект, активна epica, ID типів завдань, список завдань). Це джерело істини, з якого читають skills Jira й Tempo.
- `.claude/rules/local/vault-*.md`, твої прив'язки для кожного проекту (префікси, шляхи коду, розташування vault), завантажуються для конкретних папок.
- [CLAUDE.local.md](CLAUDE.local.md), твоя персона й контекст, імпортовані в [CLAUDE.md](CLAUDE.md) через `@import`.
- `.claude/skills/ba-track-jira/jira.env` та `.claude/credentials/`, секрети, у .gitignore.

Правило одне: `CLAUDE.local.md`, файли з суфіксом local, `.claude/rules/local/` і лог трекуються у твоєму приватному `origin` (це твої докази й контекст) і не потрапляють у ядро. У .gitignore лише секрети й машинні файли.

## Структура

```
BA-Starter-Kit/
├── README.md              ти тут: початок і карта комплекту
├── CLAUDE.md              спільні правила для Claude, плюс @import CLAUDE.local.md
├── CLAUDE.local.md        твоя персона й контекст (приватні, імпортовані в CLAUDE.md)
├── PROJECT-RULES.md       конвенції: структура папок, найменування, формати документів
├── docs/                  вся документація для людини (UA) плюс підказки й приклади
├── BABOK/                 база знань BA у Dataforest: шаблони, посібники, методи (довідка)
├── .claude/
│   ├── skills/            Claude skills, названі ba-<bucket>-<name> (плюс звичайні pdf/docx/xlsx)
│   ├── rules/             правила для машини; правила з шляхами: завантажуються для конкретних папок
│   │   └── local/         твої прив'язки для кожного проекту (vault-*.md): трекаються в origin, у ядро не йдуть
│   ├── credentials/       секрети (.gitignore); файл доступів Jira лежить у skills/ba-track-jira/jira.env
│   └── hooks/             хуки старту сесії (локальний час, пам'ять, оновлення кіта) і засіб запуску Python kit-python.sh
├── logging/               твій журнал роботи (артерія проекту); ядро поставляється тільки з порожнім шаблоном
├── workspace/             навчальний sandbox з курсу і твої чернетки
└── <назва>-vault/         робочий проєкт: окремий приватний репозиторій, git воркспейсу його ігнорує
```

`CLAUDE.md` це спільне ядро: персона, табу для виводу (без емодзі, без дефісу), правила для документів (суха довідка, вимога каже що, а не як), git, логування й mempalace, плюс `@import CLAUDE.local.md` для твоєї персони й контексту. Правила під `.claude/rules/` що оголошують `paths:` завантажуються тільки для папок, які вони охоплюють.

## Якщо це вперше

1. Установка: вхідний промпт у блоці [Почни звідси](docs/README.md#почни-звідси), що робиш ти, у гайді [Установка](docs/01_Установка/installation.md). Решту ставить скіл `ba-setup`, кожен крок закінчується рядком PASS або FAIL.
2. Робочий проєкт: [Заведення проєкту](docs/01_Установка/getting-started.md).
3. Далі: [Як я працюю](docs/02_Як%20працювати/how-i-work.md), метод; [Щоденний ритм](docs/02_Як%20працювати/daily-loop.md), щоденний ритм.

Щось перестало працювати: скажи "перевір установку".

Найшвидший старт: блок [Почни звідси](docs/README.md#почни-звідси).

## Документація

Уся документація і навігація, у [docs/](docs/README.md), єдина точка входу. Там гайди по темах (установка, робота, вимоги, прототип і деплой, інтеграції), [каталог скілів](docs/07_Довідник/скіли.md) по бакетах, приклади й промпти. Оновлення кіту, у [CHANGELOG.md](CHANGELOG.md).

## База знань BA (BABOK)

Готові шаблони й методи з Dataforest (BRD, SRS, Use Case, Personas, RACI, Risk Register, порядок денний відкриття, контрольні списки, приклади). Навігатор: [BABOK/INDEX.md](BABOK/INDEX.md).

Це довідка, тільки для читання: візьми потрібний шаблон, скопіюй його у свій вольт (`<назва>-vault/`) і заповни, не редагуй master. Сторонні книги не є частиною комплекту (авторські права); посилання на них в [BABOK/NAV - Google Drive links.md](BABOK/NAV%20-%20Google%20Drive%20links.md).

## Skills

Skills названі `ba-<bucket>-<name>` у п'яти bucket'ах: `ba-triage-`, `ba-docs-`, `ba-req-`, `ba-discovery-`, `ba-track-`. Імпортовані файлові утиліти (`pdf`, `docx`, `xlsx`) зберігають звичайні імена. Ти майже ніколи не назвеш skill сам; ти описуєш завдання й Claude вибирає його, або явно викликаєш з `/ba-<bucket>-<name>`. Повний каталог з тригерами: [каталог скілів](docs/07_Довідник/скіли.md). Щоб поділитися skill зі командою, відкрий PR проти спільного core remote (`dataforest-ai/BA-WorkSpace-Claude`).

## Твоє робоче поле

- [workspace/README.md](workspace/README.md), навчальний sandbox і чернетки.
- Робочі проєкти, у вольтах `<назва>-vault` у корені воркспейсу, кожен окремим приватним репозиторієм: [Заведення проєкту](docs/01_Установка/getting-started.md).
- [logging/](logging/README.md), твій журнал роботи, артерія проекту. Це особисте й відстежується у твоєму приватному git (докази й контекст); спільне ядро поставляється тільки з порожнім шаблоном журналу.
